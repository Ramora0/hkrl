## 2. Design decisions

**Physics through a vtable, not through `phys_*` symbols.** `hero_phys_ops` has one entry per Rigidbody2D/transform/
Physics2D operation the decomp performs (`get/set_pos`, `get/set_vel`, `gravityScale`, `localScale.x`, `isKinematic`,
`layer`, `Physics2D.Raycast`, `Physics2D.BoxCast`, NailSlash collider enable). The core binds each entry to
`sim/core/phys.h` at world creation; the harness binds them to Python. Reasons: `sim/hero` links and tests without
`sim/phys`; every `rb2d.velocity` read/write in the decomp stays a call, so the FixedUpdate write/read-back sequence
(`HC:1126-1141` wall-slide ramp, `HC:993-1011` recoil) is preserved literally. `col2d.bounds` is computed from the
body position + `heroColliders[0].offset/size` (`hero_col_bounds`): the dumped `bounds.size` equals `size`, so
`edgeRadius` is **not** part of `bounds` (physics.json#heroColliders[0]).

**FSM / animator side through `hero_hooks`.** Every `SendEvent` HeroController raises is a `fsm_send_event(target,
name)` with the target enumerated (`FSM_PROXY`, `FSM_SUPERDASH`, `FSM_THORN_COUNTER`, `FSM_SPELL_CONTROL`,
`FSM_DASH_BURST`, `FSM_DAMAGE_EFFECT`, `FSM_FALL_TRAIL`, `FSM_ORBIT_SHIELD`, `FSM_CAMERA_SHAKE` (bool var
`RumblingFall` + `EnemyKillShake`), `FSM_SOUL_ORB`, `FSM_SOUL_VESSEL`, `FSM_RUN_EFFECT`, `FSM_SHADOW_RECHARGE`); the
slash FSM `direction` write (`HC:1469-1494`) is `slash_fsm_set_direction`; `animCtrl.UpdateState/FinishedDash/
StopAttack/PlayClip/playLanding/Stop|StartControl` are `anim_*`; prefab spawns / audio / vibration / particle toggles
are one `effect(name)` hook (cosmetic — never touches traced state). Unbound hooks are counted
(`dropped_fsm_events`, `dropped_effects`, `dropped_rng_draws`), never trapped, so the hero can be driven alone.

**Shared PlayerData store.** `hero->pd` is the world's PlayerData for the 82 fields the hero touches (`hero_pd_field_table()`
gives name/code/offset for by-name access from worker F's `GetPlayerData*`/`SetPlayerData*` actions, HealthManager and the
obs packer). Soul on a nail hit is `HealthManager.cs:459` → `HeroController.SoulGain()` (`HC:2081-2116`: +11 below
`maxMP`, +3/+8 with charms 20/21; 6/+2/+6 into the reserve once full) → `hero_soul_gain`; the other pokes
(`hero_add_mp_charge`, `hero_add_mp_charge_spa`, `hero_take_mp[_quick]`, `hero_take_reserve_mp`, `hero_set_mp_charge`,
`hero_clear_mp*`, `hero_add_health`, `hero_take_health`, `hero_max_health*`) are listed with their `HC:` lines in
`hero.h`; each updates `pd` through the ported `PlayerData` internals (`PD:4779-4844`, `:8582-8643`) — caps, soul-limited
`maxMP` 66, reserve overflow/clamp — and raises the soul-orb / soul-vessel / ProxyFSM events the decomp raises.

**Reverse direction (FSM → hero).** Ported as public functions with the decomp's names: `hero_relinquish_control[_not_
velocity]`, `hero_regain_control`, `hero_ignore_input[_without_reset]`, `hero_accept_input`, `hero_set_cstate(name,
value)` (reflection by name, `HC:2853` → HeroControllerStates.cs:128), `hero_affected_by_gravity`, `hero_start/
end_cyclone`, `hero_set_start_with_*`, `hero_bounce*`, `hero_recoil_*`, `hero_start/stop_mp_drain`, `hero_add_health`,
`hero_soul_gain`, `hero_set_damage_mode_int` (= `SetDamageModeFSM`), `hero_reset_quake_damage`,
`hero_can_nail_art` (side effect), the Can* queries, `hero_get_state`. The complete list of what the Knight's FSMs call
was extracted from `analysis/fsm/GG_Hornet_1.json` (`harness/tests/test_hero.py` `load_fsm_calls`) — worker F's actions
`CallMethodProper(HeroController.*)` / `SendMessage(Knight, *)` must map onto these.

**Coroutines as counters, one resume rule** (`hero_coroutines`, `hero_coroutine_phase`). Unity's rules are not in any
decomp (Q-dmg-8); the port uses the rule that reproduces the two measurements, stated once:
* a coroutine that yields during frame F *before* F's coroutine phase first resumes / first accumulates `dt` at F+1's
  coroutine phase (`co.*_skip` flags, set from `co.phase_ran` which `hero_set_clock` clears on a new frame);
* `yield return StartCoroutine(<empty FreezeMoment>)` (`HC:3829`, Q21) = one frame — frozen frames count;
* `WaitForSeconds(s)` = accumulate the scaled `Time.deltaTime` of each coroutine phase in float32 (0 on frozen frames)
  and resume when the sum `>= s`; except `Invulnerable`'s waits, which follow the native rule
  (analysis/native_specs/native-playerloop.md §4.2, §7): the key is the absolute double dynamic time of the yield
  plus `(double)s`, and a due key resumes in `update_delayed` **after** the env coroutine
  (`hero_coroutine_after_env`, its `co.after_env_ran` skip).  The 1.3 s wait yielded at F+1 comes due at F+66
  (65 × (double)0.02f ≥ (double)1.3f), after FRAME F+66: `invulnerable` is set on FRAMEs F..F+66 and the knight
  can be hit from F+67's physics step (`tools/iframe_window.py`: over the 160 polbat episodes the game lands 28
  of 56 contact calls at +67 and none earlier; the sim's replays land 28 of 66 at +67 and none earlier).
Measured consequences (all nine corpora): `recoilFrozen` set on exactly 1 FRAME per landed hit (§4), `invulnerable`
set on exactly **67** FRAMEs (`DAMAGE_FREEZE_DOWN` → 1 live frame, `INVUL_TIME` 1.3 → 65 more live frames, the
clear after that frame's FRAME), `recoilTimer` reaches 0.22 (11 increments) before `CancelDamageRecoil`, `attack_time`
resets on its 15th tick (14 × 0.02f = 0.27999997 < 0.28f). Hero coroutines resume **before** the mod coroutine that
emits FRAME, except the `Invulnerable` resumes above. `CheckForTerrainThunk` iterates once per coroutine phase; once `terrainHit`
is true the decomp's loop can never exit (`thunkTimer` is only decremented while `!terrainHit`, `HC:4364-4422`) — the
slot is released because nothing observable remains (comment in code).

**Input timing.** One `hero_input_tick` per rendered frame (live and frozen), before `hero_update`; that is one
`InputManager.UpdateInternal` (Q-hero-12: either `updateMode` gives one tick per frame under R2). Key bits written by
`hero_apply_action` on frozen frame F are seen by the tick of F+1 (`WasPressed` edge there) and acted on by the
FixedUpdate of F+2 — verified by the replay (0 input mismatches over the 2 100 STEP events of the nine corpora). The DPad ±0.7071
normalisation (`DeadZone.Separate`, InputDevice.cs:681-706) is ported; `move_input = 0.7071` appears in the traces
only through `SetStartingMotionState` (`HC:4264`, unfiltered `moveVector.X` on `RegainControl`) and replays exactly.

**Clocks.** `hero_set_clock(frameCount, deltaTime, timeSinceLevelLoad)`: `Time.frameCount` for `Update10`
(`HC:5108`), `Time.deltaTime` (0.02 live / 0 frozen; the core passes 0.02 for FixedUpdate calls — the one
`Time.deltaTime` read in a fixed context is `Dash()` `HC:1520`, Q-hero-9), `Time.timeSinceLevelLoad` for
`altAttackTime` (§5).

**ActionDecoder** (`hero_apply_action`): line-for-line `PC:321-405` including the hard-commit machine. The hold-lock
divisor `kCaptureDeltaTime` is a runtime knob, `hero_set_commit_capture_dt(h, dt)` / `in->commit_capture_dt`, **default
0.00848f** = the oracle's constant (`PC:295`, Q20) so the sim reproduces the recorded game (nail 89 / focus 30 / dream
nail 177 / super dash 59 locked steps at fpw=2); `0.02f` selects the R2-correct lengths (38 / 13 / 76 / 26 — the
`Math.Ceiling` argument is a double, §9) once FullKnight switches. Unit tests cover both.

## 3. The replay harness (`harness/tests/test_hero.py`)

Per live frame: pose ← `HC_FIXED_PRE`; `hero_fixed_update` + `hero_slash_fixed_update`; compare velocity with
`HC_FIXED_POST`; pose ← `HC_UPDATE_PRE`; synthesised physics callbacks; injected external calls; compare velocity
with `HC_UPDATE_PRE` again (the recorded post-solve velocity already contains what the callbacks wrote);
`hero_input_tick`; Knight-FSM transitions recorded before `HC_UPDATE_PRE`; `hero_update`; compare with
`HC_UPDATE_POST`; late FSM transitions; `hero_coroutine_phase`; compare everything with FRAME; `hero_box_late_update`.
Per frozen frame: pose ← `HC_UPDATE_PRE`; tick; `hero_update(dt=0)`; compare; coroutine phase; `hero_apply_action`
with the STEP action; the resulting key bits are compared with the next FRAME's `input`.

Seed: `hero_init_from_dump` then the first FRAME's fields/cstate/pd/pose override it (the only field the dump and the
trace disagree on is `preventCastByDialogueEndTimer`, a boot-clock value: dump −15.97 vs trace −17.29, Q-phero-5);
the ActionDecoder commit state is rebuilt by replaying the STEP events before the seed FRAME.

Harness-only physics stand-ins (these are **not** sim rules; worker P pins them, Q-phero-1/2):
* raycasts/boxcasts answered from `scene.json` layer-8 statics (3 boxes, the `Roof Collider` polygon, 6 tilemap edge
  chains), with `queriesStartInColliders=false` honoured by skipping shapes containing the origin;
* contact "touching" = hero AABB (`size/2 + edgeRadius + 0.02`) overlapping a non-trigger layer-8 shape; the 0.02 is
  `2 × Physics2D.defaultContactOffset`;
* callbacks: a contact **persists/ends** by the pre-solve pose (Box2D collide precedes solve), a **new** contact begins
  from the pre-solve pose, or from the post-solve pose only when the recorded solve moved the body off its free-flight
  prediction (a TOI/contact solve happened). `OnCollisionStay2D` is not delivered on the enter step. Three trace
  frames discriminate these: r2_move f25184 (TOI landing: Enter + `BackOnGround` in-step), f25257 (free flight ending
  inside the skin: Enter next step, `hero_state` stays airborne), r2_rand1 f25272-25275 (wall: Enter at 25273 sets
  nothing, Stay at 25275 sets `touchingWallL`);
* HeroBox trigger callbacks (damage) are delivered **before** collision callbacks (r2_jump f24630: a hit on the jump
  step leaves `onGround` true because `OnCollisionStay2D` sees `no_input`).
* external calls replayed from the trace: `HERO_DAMAGE` → `hero_box_check_for_damage` (side from Hornet's root
  `pos_x` vs the hero — `Needle`/`Hit ADash` are not HealthManagers so the boss root stands in; `hp_after` is checked),
  `ENEMY_DAMAGE` → `hero_soul_gain` (HealthManager.TakeDamage → SoulGain is worker F's), Knight `FSM_TRANSITION` →
  the hero calls the entered state performs (from the FSM dump, in action order, stopping at the action that can send
  the event that took the FSM out of the state — a reconstruction of PlayMaker OnEnter, worker F's runtime);
  transitions raised from inside `TakeDamage` (`HeroCtrl-HeroDamaged` cascade → `Superdash Cancel` → `RegainControl`)
  are applied inside the `fsm_send_event` hook so they land between `SendEvent` and `StartRecoil` as in `HC:1928-2014`;
  rising edges of `bouncing`/`shroomBouncing` (NailSlash trigger vs the boss, physics slot) and
  `recoilingLeft/Right` (HealthManager path, lands after `HeroController.Update`: r2_attack f24650) stand in for
  the un-synthesised knight-attack-vs-boss contacts.

## 6. Source-vs-spec disagreements found while porting (cite both)

1. `analysis/specs/hero-motion.md` 3.2c says `HeroCtrl-DashEnd` is raised "inside FixedUpdate" and `HeroCtrl-LeftGround` inside
   Update — confirmed; but the trace additionally shows `RecoilLeft/Right` from an enemy hit landing **after**
   `HeroController.Update` (r2_attack f24650: `HC_UPDATE_POST` v.x = −8.3, FRAME v.x = +3.75, `recoilingRight` set)
   whereas `analysis/specs/damage-path.md` 1.5 places `HealthManager.Invincible()` in the physics phase. The record order wins; the
   harness injects the proxy after `hero_update`. Worker F should port HealthManager's hit handling in an Update-phase
   slot (Q-phero-6).
2. `analysis/specs/hero-motion.md` 1.3 states collision callbacks are the only in-step source of `onGround = true` besides the
   Update-phase paths; the port confirms, but the **step** on which `OnCollisionEnter2D` fires is not the step the
   body first overlaps the skin: r2_move f25257 shows the body at 28.40535 (below the 28.40812 rest) with
   `hero_state = airborne` and v.y = −18.012 unchanged. The spec's "one-step landing" table (1.2) is correct for TOI
   landings only. Q-phero-1.
3. `analysis/specs/damage-path.md` 1.3 item 9 counts the FreezeMoment yield as "exactly 1 recorded frame"; the port refines it to
   "1 frame including frozen frames" (r2_rand1 24994: hit on the 2nd live frame → `recoiling` true at the frozen
   frame 24995 → recoil velocity at 24996).
4. `hero.json#attackDuration = 0` is stale in-flight state (`analysis/specs/hero-motion.md` D21): the port initialises it from the
   dump (it *is* 0 at SceneReady — the trace's first FRAME agrees) and `Attack()` latches 0.28 (`HC:1330-1337`).
5. `analysis/specs/PORT-BRIEFS.md` says "325 fields"; the trace header and `hero.json` carry 214 primitive + 140 non-primitive
   fields (354 in the dump incl. properties); the port models the 214 primitives + 9 Vector2/array fields.

## 7. Interface requests (sim/core, orchestrator-owned)

* Scheduler order per frame (documented at `hero.h` "per-frame entry points"): `hero_set_clock(…, 0.02f, …)` before
  `hero_fixed_update` (accepted); `hero_coroutine_phase` after `hero_update` and before the FRAME/obs emission
  (accepted); `hero_input_tick` once per frame, before `hero_update`, after the physics callbacks; `hero_box_late_update`
  in the LateUpdate slot.
* `phys.h`: no change needed. The core binds `hero_phys_ops` to `phys_*`; note the hero needs from the raycast/boxcast
  result: `point`, `isTrigger`, and the marker components `SteepSlope`/`NonSlider`/`NonThunker.active` on the hit
  collider, and from a contact event: normal, layer, `HeroWalkable` tag, `NoHardLanding`/`SteepSlope`/`NonSlider`.
  `phys_event` carries normal + shape ids; the core must resolve the shape id to those flags (scene tables have the
  component list).
* `hk_rng *rng` on the hero must point at the world stream (draws at `HC:1862-1898`, `HC:4402`, and the jump / wall-jump audio pitch, §11.1).
* Scheduler: `hero_anim_update(h)` after `hero_update(h)` on every frame (live and frozen); worker F binds `hero_tk2d_ops` (§11.2); the core emits the FRAME anim block from `hero_anim_current`.
* **`HC_UPDATE_POST` must be emitted between `hero_update` and `hero_coroutine_phase`** (live and frozen frames). The
  oracle samples it in the MonoMod post-hook of `HeroController.Update` (`oracle/Oracle/TraceRecorder.cs:256-259`),
  before any coroutine resumes; `sim/core/sim.c:309-311` and `:333-334` currently emit it after
  `hero_coroutine_phase`, so every write the coroutine phase performs (terrain-thunk recoil, `recoiling` set by
  StartRecoil, `invulnerable` cleared) shows up one record early in the sim and is reported as a divergence although
  the FRAME record matches (§10).
* `sim/CMakeLists.txt` `-DHKSIM_MODULES="core;hero"` builds and links; while `sim/core/sim.c` was mid-edit
  (`hksim_abi_version` defined twice) the tests were run against a hero-only DLL built with the same flag set
  (`sim/build-h/hksim_hero.dll`); the cmake DLL now builds and gives identical results.

## 8. Open questions

### Q-phero-1 — when Unity delivers OnCollisionEnter2D/Stay2D/Exit2D relative to the solve
The hero's `onGround`/`touchingWall*`/`ledgeBufferSteps`/`headBumpSteps` transitions are driven by the collision
callbacks (`analysis/specs/hero-motion.md` 1.3), and the recorded traces pin three cases: a landing that penetrates within the step
fires Enter and `BackOnGround` in that step (r2_move f25184), a step that ends with the body inside the contact skin
but not overlapping fires nothing until the next step (f25257: `hero_state` still airborne, v.y −18.012 unchanged
at 28.40535), and a wall approach fires Enter one step after arrival and Stay the step after that (r2_rand1
25272-25275, `touchingWallL` set only on the Stay). The harness encodes this as "persist/end from the pre-solve pose,
begin from the pre-solve pose or from a solver-corrected post-solve pose, no Stay on the Enter step" and it reproduces
all nine corpora, but it is a fit to recorded outcomes, not a rule from a source. Settled by: worker P's contact
begin/end semantics from `sim/phys` (Box2D collide-before-solve + TOI begin), which the core then feeds through
`phys_events()`; the harness's rule and margin (`2 × defaultContactOffset`) should be checked against it.

### Q-phero-2 — order of trigger vs collision callbacks within one physics step
r2_jump f24630 has a HeroBox hit and a ground Stay in the same step; `onGround` stays true in the trace, which is
only reproduced if `TakeDamage` (→ `SetState(no_input)`) runs before `OnCollisionStay2D` (`HC:4912` early return).
The harness therefore delivers HeroBox trigger callbacks before collision callbacks (`CALLBACK_ORDER`). This is the
hero-side instance of `analysis/specs/damage-path.md` Q-dmg-11(a). Settled by: the phase-marker capture Q-dmg-11 asks for, or worker
P's event ordering in `phys_events()` (the core must then preserve it when dispatching to the hero).

### Q-phero-3 — paths ported from code with zero trace coverage
Constant in all nine corpora and therefore unverified (`UNVERIFIED` comments in `hero.c`/`hero_damage.c`): hard
landing (`DoHardLanding`, `hard_landing` timers/failsafe), `dash_landing` (charm 31), wall-jump early release, the

## 9. Mono evaluation-stack audit (docs/float-parity.md amendment 2026-08-31)

rewritten as double arithmetic with one `(float)` cast per C# store, and the nine corpora were re-run: all still
full-length. Statements changed:

| `HC:3471` | `(WJ_KICKOFF_SPEED - RUN_SPEED) / (float)WJLOCK_STEPS_LONG` | double difference and division, one rounding at the store (= 0.77000000238… either way for 16/8.3/10, but the rule is applied) |

| `Utility.cs:130-152` `ApplyDeadZone` | `(value ± lowerDeadZone) / num` | double, rounded at the float return |
